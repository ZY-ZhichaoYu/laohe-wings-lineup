## 界面与开源参考

- 手机默认看阵容，使用“看阵容 / 调整 / 导出”切换；在调整界面也能直接导出完整海报。

- [Tabler](https://github.com/tabler/tabler/blob/dev/core/scss/ui/_segmented.scss) 用于分段控件与工具区设计参考，没有引入 Bootstrap 或复制整套样式。
- 实际采用 [Lucide](https://github.com/lucide-icons/lucide) 的 6 个静态 SVG 图标：download、sliders-horizontal、users-round、rotate-ccw、search、trophy。代码固定保存在 `assets/ui-icons.js`，无额外联网加载；完整 ISC/Feather MIT 许可位于 `assets/lucide/LICENSE.txt`。来源提交为 `5aae256c6479aef74c609b536d10675c97c714e3`。

## 本地验收

72 项 Node 测试通过；语法与生成数据一致性检查通过，静态构建成功。新增回归覆盖默认阵容升级、旧无 ID 存档、伤停只应用一次、照片和互动保留、主客场照片回退、编辑行与人物索引一致性、清除照片后刷新与再次上传。

本地 Chromium 已检查手机查看/调整切换、搜索伤员、恢复默认及备份、两队指定首发、赖飞扬照片加载、陈炫教练伤停显示和手机 PNG 导出。真实 CloudBase 数据库、云存储规则、多人同时使用和微信/iOS 真机仍需发布后验收。

## 发布与回退

最新实际交互检查见 [第三轮调试记录](DEBUG_20261029.md)，包含张子冲主客场新版、旧缓存升级，以及鼠标与触屏拖拽修复。

代码推送与网站部署是两个不同步骤。GitHub Pages 使用 `.github/workflows/pages.yml`，只在检查、测试、构建全部成功后发布 `dist/`；GitHub Pages 为静态本地模式，不启用 CloudBase 写入。

CloudBase 必须配套部署完整 `cloudfunctions/publishLineup/` 和 `dist/`，详见 [部署说明](../CLOUDBASE_SETUP.md)。不要覆盖已有 EDIT_SECRET、路由或存储规则。上线前保存现有云函数版本与数据库备份；若发布/互动/图片导出回归，回退配套前后端版本，不删除赛事文档。旧 eleven-a-side 文档仍为 `lineups/current`。
