## 审查结论与修复

参考截图确实指出了需要关注的方向，但不能全部当作当前代码的事实。基线已有服务端 `EDIT_SECRET` 校验、固定的 Node SDK 直接依赖、部分 CDN SRI 和数据库事务；仍有可绕过或退化的路径。本次按实际代码继续修复。

| 问题 | 本次处理 |
| --- | --- |
| 图片代理允许任意公网目标，IP 字面量与重定向有风险 | 限定精确 HTTPS 域名和 443 端口，拒绝凭据及 IP 字面量；重定向逐跳复核，连接仅用已校验的公网 IPv4。本环境云存储文件由 SDK 换取临时 URL。 |
| 事务失败后退回普通读改写，重新引入丢更新 | 移除不安全回退；事务不可用或失败时拒绝写入。 |
| 旧阵容整包覆盖新评价、报名、投票 | 发布在事务中比较 `baseUpdatedAt`，并保留服务器当前互动记录。 |
| 云监听可能覆盖未发布草稿；发布过程中遗漏更新 | 草稿保留原始版本，缓存并协调发布过程中的更新，忽略倒序版本；刷新恢复草稿，显式重新载入才丢弃。 |
| 公开设备标识被当作删除评价的凭据 | 删除评价/回复改为服务端管理员鉴权，不再凭公开 deviceId 判断所有权。 |
| 提交失败仍清空评论、附件并假称已保存 | 在线失败保留输入及附件；未获得明确成功响应时不加入已提交列表。删除也必须收到明确成功确认。 |
| 号码被当作人物身份，同号新队员可能拿到旧照片 | 八人制加入稳定人物 ID，按姓名匹配照片后再核对号码；9、14、41 号不会串图。 |
| 换人后离场球员丢失 ID，刷新出现重复名单 | 修复替补转换与状态合并，回归覆盖换人、保存及刷新后的身份唯一性。 |
| 队长、阵型与名单写死 | 队长优先使用显式字段；每队独立阵型、人数、名单、云文档、草稿与预设。 |
| 一个巨大 HTML、数据副本易漂移 | 分离 HTML、样式、主逻辑、界面脚本与赛事模型；从 JSON 自动生成浏览器回退数据，加入 Node 测试、语法检查及 CI。 |
| UI 层级杂乱、手机操作密集 | 新建双队导航、名单/照片状态、折叠管理入口；桌面并排工作台，手机单栏，加入直达阵容链接。 |
| 导出与屏幕渲染不一致 | 改用 html2canvas 支持的球场条纹；提高替补/领队/页脚对比度；调整八人制门将与后卫间距。 |

## 验证记录

自动检查入口为 `npm.cmd run check`、`npm.cmd test`、`npm.cmd run build`。测试运行真实的赛事模型及相关前端函数，云端事务与网络边界使用模拟对象，不向生产数据库写入测试数据。

最终结果：52 项测试全部通过，语法/数据一致性检查通过，`dist/` 构建成功，`git diff --check` 无空白错误。

本地 Chromium 验证包括：

- 1440×1000 桌面与 390×844 手机宽度布局；手机页面无水平溢出。
- 双队和十一人制切换；两队人数与队长正确，阵型与草稿互相隔离。
- 8 人制三种、11 人制四种阵型：首发数正确，球员卡片不重叠、不越出球场。
- 替补换上首发、刷新后名单无重复，缺照片者显示空白占位。
- 本地补照片经过真实文件处理与 JPEG 转换，刷新后仍存在；测试照片已从草稿清除，未修改原始人物素材。

4. 原人物素材总量较大，当前 assets 约 176 MB；本次保留原图，未完成全站图片衍生尺寸/压缩管线或弱网性能验收。
5. 主逻辑已从 HTML 分离，但仍是较大的脚本；可继续按排阵、互动、存储和导出拆分。旧小程序未扩展本次双队功能。
